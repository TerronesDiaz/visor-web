# visor-web 3.2.1

El visor ya no interfiere con una actualización en curso cuando alguien lo vuelve a abrir, y con el actualizador nuevo se queda abierto mostrando el avance en lugar de cerrarse al pulsar Instalar.

Si el visor se abre a media actualización (por ejemplo, desde el acceso directo o al iniciar Windows), ya no enciende Docker ni el POS. Antes volvía a levantar el POS que el actualizador había detenido para respaldar, y se podía vender durante el respaldo o la migración; esas ventas se perdían si después la actualización se revertía. Ahora muestra la ventana de avance y se cierra, o espera con el POS cubierto, según el actualizador instalado. También se bloquean el cambio de tienda y el alta mientras haya una actualización.

Con el actualizador de Terrones POS 2026.11.01.4 o posterior, Instalar actualización ya no cierra el visor: cubre el POS, muestra los pasos (respaldo, instalación, base de datos, comprobación) y vuelve a abrir la tienda al terminar. Solo se cierra un momento al final si también se actualiza el visor, y se abre solo. Si la actualización falla, lo dice y ofrece abrir el POS con la versión anterior.

Un archivo install.lock que quedó de un reinicio ya no deja la caja en "Instalando" para siempre: el visor solo considera activa una actualización si el actualizador mantiene abierto el candado. Si una solicitud lleva cinco minutos sin que nadie la atienda, el visor abre el POS normalmente y Estado de Terrones POS indica que hay que ejecutar Install-TerronesUpdate.ps1.

La ventana de avance ya no se abre repetida si el visor se abre varias veces durante la actualización.

Validación: pruebas del estado de actualización con un candado sostenido por PowerShell igual que el actualizador, con un candado abandonado, con una solicitud sin atender y con avance de un intento anterior; revisión visual de las pantallas de avance y de error a 1366x768.
