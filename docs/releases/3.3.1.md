# visor-web 3.3.1

Al encender la caja ya no aparece la ventana de Docker Desktop, y el visor ya no se detiene con "No fue posible iniciar los servicios en segundo plano" mientras Docker termina de arrancar.

Docker Desktop se registraba para abrirse solo al iniciar Windows, con su ventana al frente, aunque su propia opción de inicio automático estuviera apagada. Al mismo tiempo el visor intentaba encenderlo; esa orden fallaba porque Docker ya iba arrancando, y el visor mostraba el error hasta que alguien pulsaba Reintentar. Ahora el visor quita esa entrada de inicio de Windows (solo para el usuario de la caja) y enciende Docker él mismo en segundo plano, sin ventana. Si Docker ya está arrancando, espera hasta tres minutos a que responda en lugar de pedir otro inicio, y si la orden de inicio falla también sigue esperando. El error solo aparece si Docker de verdad no responde en ese tiempo.

En la primera vez que se abra esta versión, Docker puede mostrar su ventana una última vez, porque ya se había abierto con Windows. Desde el siguiente encendido arranca oculto.

Validación: pruebas del arranque de Docker con reloj simulado (Docker ya disponible, arranque en frío, Docker abierto por Windows, orden de inicio fallida que después responde, Docker que nunca responde) y de la entrada de inicio de Windows (se quita cuando existe, no se toca cuando no existe y un fallo al quitarla no impide abrir la tienda). Detección de procesos con `tasklist` comprobada en Windows. No probado en una caja real.
